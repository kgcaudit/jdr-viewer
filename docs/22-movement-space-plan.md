# 22. 이동기록(휴대폰 GPS) 공간 분리 계획

## 왜 고치나

지금은 휴대폰 GPS 대조를 **재생 화면의 탭(동선)** 으로 붙였다. 그런데
재생 화면(폴더·파일 선택 뒤)의 탭들은 모두 **블랙박스 자료 하나를 분석**하는
공간이다(요약·구간·지도·센서·대화·내보내기). 여기에 성격이 다른 **외부 GPS**를
끼우면 계층이 어긋난다.

→ **시작화면에서 공간을 둘로 나눈다.** 블랙박스(JDR)와 이동기록(휴대폰 GPS)을
각자 관리하고, 대조는 둘을 잇는 별도 동작으로 둔다.

## 현재 구조 (파악한 것)

- 화면 전환은 `views = { empty, loading, error, calendar, main }` + `showView(name)`.
  시작화면은 `view-empty`(폴더/파일 열기 버튼).
- 블랙박스 흐름: `folder-input` → `openFolder()` → `folderState`(세그먼트·달력·파일맵)
  → `view-calendar`(달력) → `openDay()` → `view-main`(재생).
- **인덱스(증분 로딩) 모델**:
  - `probe-cache`(IndexedDB): 파일별 헤더 프로브 결과를 캐시. 키 = `이름|크기|수정시각`.
    파일이 바뀌면 자동 재프로브.
  - `jdr-index.json`(파일): 폴더에 저장해 다른 기기로 옮김. 있으면 헤더 훑기 건너뜀.
  - 즉 **처음 열 때 인덱스로 목록을 세우고, 새/바뀐 파일만 추가로 읽는다.** ← 유지 대상.
- 차량 GPS 좌표는 **인덱스에 없다**(개수만 있음). 실제 좌표는 재생 시 스캔
  (`RecordScanJob`)이 모아 `session.records.gps`에 담는다.
- 이미 만든 재사용 자산: `core/phone-track.ts`(도와줘 파서), `core/track-match.ts`
  (대조·분류). **UI 위치만 옮기면 되고 엔진은 그대로 쓴다.**

## 제안 구조

### A. 시작화면 — 두 입구

`view-empty`를 **모드 선택**으로 바꾼다.

```
┌───────────────┐   ┌───────────────┐
│  블랙박스      │   │  이동기록      │
│  (JDR Viewer)  │   │  (휴대폰 GPS)   │
│  폴더/파일 열기 │   │  위치기록 올리기 │
└───────────────┘   └───────────────┘
```

- 상단바에도 두 모드를 오가는 표시를 둔다(블랙박스 ↔ 이동기록).
- 각 모드는 **자기 인덱스를 초기에 한 번 로딩**하고, 이후엔 델타만 추가.

### B. 이동기록 공간 (신규)

블랙박스 흐름을 그대로 본뜬다:

1. **올리기(다중 파일)** — `이동기록 올리기`는 **여러 파일 동시 선택** 허용
   (`multiple`). 하루가 여러 응답으로 쪼개졌어도(2,000건 상한) 한 번에 올린다.
2. **파싱·병합** — 각 파일을 `parsePhoneTrack`으로 읽어 **날짜별로 나눠**
   저장소에 병합. 같은 시각(초 단위) 점은 하나로 — **이미 있던 기록과 새 기록이
   자동 합쳐진다.** (도와줘 2,000건 상한으로 잘린 하루가 여러 업로드로 채워짐)
3. **이동기록 인덱스(IndexedDB, 신규 저장소)** — `probe-cache`와 같은 패턴.
   - 날짜별 문서: `{ dayKey, points: [{t,lat,lon,speed,acc,act}], count, updatedAt, source[] }`
   - 좌표를 **직접 저장**한다(블랙박스와 달리 업로드 콘텐츠라 디스크 재선택이 없음).
   - 초기 진입 시 저장된 날짜 목록만 로딩, 새 업로드분만 병합 추가.
   - 용량: 하루 ~2,000점 × 5필드 ≈ 수십 KB. 한 달 ~60만 점도 IndexedDB로 감당.
4. **날짜 목록/달력** — 저장된 이동기록을 **달력**으로(블랙박스와 같은 UI 재사용)
   보여주고, 날짜를 고르면 **그날 동선**(지도 궤적 + 주행/보행/체류 요약)을 본다.
5. **내보내기** — 날짜별/기간별 CSV.

### C. 대조(블랙박스 × 이동기록) — 이어 주는 다리

두 공간을 나눴으므로 대조를 **명시적 동작**으로 둔다. 두 갈래 중 택1:

- **(C-1) 이동기록 쪽에서 대조** — 이동기록의 어떤 날짜를 보다가
  "이 날짜를 블랙박스와 대조"를 누르면, 같은 날짜의 **차량 GPS**를 끌어와 겹친다.
- **(C-2) 대조를 제3의 화면으로** — 날짜 하나를 고르면 양쪽(차량·휴대폰)을
  나란히 불러와 대조.

**두 경우 모두 핵심 결정 하나가 걸린다 ↓**

## 반드시 정할 것 — 차량 GPS를 어디서 얻나

대조하려면 그날 **차량 GPS 트랙**이 필요하다. 지금은 재생 스캔으로만 얻는다.
이동기록 공간(재생과 분리)에서 대조하려면 두 방법뿐이다:

- **(가) 차량 GPS를 인덱스에 저장** — 인덱싱 때 각 파일의 GPS를 간소화해
  `jdr-index.json`/캐시에 실어 둔다. 그러면 재생 없이도 그날 차량 트랙을 바로 얻음.
  사용자가 앞서 말한 **"인덱스 시 GPS를 기록해 활용"** 이 바로 이것. **권장.**
  - 비용: 프로브가 헤더(512B) 외에 GPS 패킷도 읽어야 해 인덱싱이 다소 무거워짐.
    간소화(예: 5초에 1점)로 용량·속도를 잡는다. 인덱스 버전 v8로 올림.
- **(나) 대조할 때 그 날짜 블랙박스 폴더를 열어 스캔** — 인덱스 안 바꿈. 대신
  대조 전에 블랙박스 폴더가 열려 있어야 하고 스캔을 기다려야 함. 공간 분리 취지와
  약간 어긋남.

## 재사용/이동 정리

- `core/phone-track.ts`, `core/track-match.ts` — **그대로 유지**.
- 지금 재생 화면의 **동선 탭은 제거**하고, 그 로직을 이동기록 공간으로 옮긴다.
- 달력·지도(Leaflet) 컴포넌트는 이동기록 공간에서 **재사용**.

## 단계 (결정 후)

1. 시작화면 두 입구 + 모드 전환 뼈대.
2. 이동기록 저장소(IndexedDB) + 다중 업로드 + 날짜별 병합.
3. 이동기록 달력 → 날짜별 동선(지도+요약).
4. 대조 다리(C-1/C-2 중 택) + 차량 GPS 소스(가/나 중 택).
5. 재생 화면 동선 탭 제거.

## 결정 요청

1. **시작화면 분리** — 두 입구(블랙박스 / 이동기록)로 나누는 방향 OK?
2. **대조 위치** — (C-1) 이동기록 쪽에서 / (C-2) 별도 대조 화면?
3. **차량 GPS 소스** — (가) 인덱스에 저장(권장) / (나) 그때 폴더 열어 스캔?
4. **이동기록 저장 범위** — 브라우저(IndexedDB)에 계속 쌓기 OK? (파일 내보내기도 제공)
