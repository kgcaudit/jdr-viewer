# 소리가 "지직" 깨지는 원인과 고침

> 보고: **"이번 버전은 음성 부분이 자주 깨져서 들려."**

## 먼저 확인한 것 — 최근 변경 탓이 아니다

의심부터 기록해 둔다. 최근 다섯 커밋에서 재생 쪽 소리 코드는 **한 줄도
바뀌지 않았다.**

```
$ git diff --stat HEAD~5 HEAD -- web/src/player web/src/core/timestretch.ts
 web/src/player/sequence.ts | 63 +++++++++++++++++++++++++++++++++-----
```

`player/audio.ts`, `player/player.ts`, `core/timestretch.ts`는 그대로다.
그러니 "이번에 넣은 것이 깼다"는 설명은 성립하지 않는다. 대신 **처음부터
있던 결함**을 이제 듣게 된 것으로 보고 소리를 놓는 방식 자체를 다시 봤다.

## 원인 — 시각을 곧이곧대로 믿었다

오디오 패킷은 8kHz s16le 조각이고, 각 패킷에는 기기가 찍은 시각이 있다.
지금까지는 그 시각을 그대로 표본 자리로 바꿔 파형을 놓았다.

```ts
const baseSample = Math.round(((ref.startMs - segStart) / 1000) * AUDIO_SAMPLE_RATE);
```

문제는 **그 시각이 표본 단위로 정확하지 않다**는 것이다. 8kHz에서 1ms는
여덟 표본인데, 시각은 ms 해상도이고 그나마 패킷을 쓰는 순간의 벽시계다.
패킷마다 1~2ms씩 흔들린다. 그래서

- 앞 패킷 끝과 다음 패킷 시작 사이에 **표본 몇 개짜리 구멍**이 생긴다.
  파형이 0으로 뚝 떨어졌다 돌아오니 "딱" 소리가 난다.
- 반대로 겹치면 **덮어써서** 파형이 끊긴다. 역시 "딱" 소리다.

패킷은 초당 다섯 번 남짓 들어오므로 이게 **초당 몇 번씩** 일어난다.
사람 귀에는 "자주 깨진다"로 들린다.

기기가 초 단위로만 시각을 찍는 경우(여러 패킷이 같은 시각)는 더 나쁘다.
전부 같은 자리에 덮어써서 소리가 통째로 사라진다.

## 고침 1 — 이어질 만하면 이어 붙인다

규칙 하나로 정리했다 (`core/audio-place.ts`).

```ts
export function placeSample(cursor: number, nominal: number): number {
  if (cursor < 0) return nominal;
  const drift = cursor - nominal;
  if (drift >= -AUDIO_JITTER_SAMPLES && drift <= AUDIO_DRIFT_LIMIT) return cursor;
  return nominal;
}
```

- **30ms보다 좁은 틈**은 시계 흔들림으로 보고 앞 소리 끝에 붙인다.
- **겹침**도 덮어쓰지 않고 뒤에 잇는다 (같은 시각이 여럿이어도 소리를 잃지 않는다).
- **30ms보다 넓은 틈**은 진짜 공백이다. 주차 모드처럼 소리가 없던 구간은
  무음으로 남아야 하므로 시각을 믿는다.
- 붙여 쓰다 **1초 넘게 밀리면** 포기하고 시각으로 되돌린다. 시각이 통째로
  망가진 파일에서 소리가 영상과 끝없이 벌어지는 걸 막는다.

자리는 파일을 열 때 한 번만 정한다. 500ms 창을 만들 때마다 다시 계산하면
창 경계에서 규칙이 갈릴 수 있다.

**재생과 내보내기가 같은 함수를 쓴다.** 들을 때와 저장한 MP4가 다르면
안 되기 때문이다.

## 고침 2 — 지나간 예약은 당기지 말고 버린다

```ts
node.start(Math.max(when, this.ctx.currentTime));   // 전
```

예약할 시각이 이미 지났을 때(구간 전환·GC 등으로 본선이 잠깐 멎으면 생긴다)
"지금"으로 당겨 넣고 있었다. 그러면 밀린 조각들이 **한꺼번에 겹쳐 울려**
뭉개진다. 한 번 밀리면 그 뒤로 계속 겹치므로 증상이 오래 간다.

이제는 지나간 만큼을 잘라 버리고 남은 데서 잇는다. 소리가 조금 빠지는 편이
뭉개지는 것보다 낫고, 영상과의 맞춤도 유지된다.

## 고침 3 — 소리가 막 시작할 때 본선을 붙잡지 않는다

구간을 열다 시각이 고쳐지면(`onLibraryFixed`) 스트립과 구간 목록을 **그
자리에서** 통째로 다시 그렸다. 하필 새 구간의 소리가 막 예약을 시작하는
순간이다. 목록이 길면 본선이 수백 ms 멎고, 그만큼 예약이 밀려 고침 2가 막던
바로 그 상황이 된다.

200ms 미뤄 몰아서 한 번만 그리도록 했다.

## 덤 — 고쳐진 뒤의 구간 번호

`recomputeLibrary()`는 목록을 **다시 정렬한다.** 그런데 재생 쪽은 자기
자리(`this.index`)를 그대로 들고 있었다. 시각이 고쳐지면서 순서가 바뀌면
그 뒤로 통지하는 구간 번호가 엉뚱한 파일을 가리킨다. 정렬 뒤에 자리를 다시
찾도록 했다.

## 시험

`test/audio-place.test.ts` — 고치기 전 코드로 돌리면 네 개가 깨진다.

- 표본 몇 개짜리 틈은 앞 소리에 붙는다
- 겹쳐도 덮어쓰지 않는다
- 여러 패킷 시각이 같아도 소리를 잃지 않는다
- 진짜 공백(5초)은 무음으로 남는다
- 시각이 200/401/601/802ms처럼 흔들려도 **무음 표본이 하나도 끼지 않는다**

## 남은 것

30ms라는 경계는 추정이다. 실제 기기가 찍는 시각이 얼마나 흔들리는지는
샘플 파일의 오디오 패킷 시각 간격을 재 봐야 정확히 안다. 너무 좁으면 흔들림을
못 잡고, 너무 넓으면 진짜 짧은 공백을 없애 버린다. 실기기에서 아직도
깨져 들린다면 이 값부터 의심할 것.
