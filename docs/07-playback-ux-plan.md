# 재생 UX 보강 계획 — 배속 음성 · 구간 선택 · 즐겨찾기

4차 실기기 피드백에서 나온 세 가지를 조사한 결과와 선택지입니다.
**실행 전에 결정이 필요한 항목은 D9~D12로 표시했습니다.**

## 1. 배속에서 음성이 안 나옴

### 원인 — 의도된 동작이었습니다

`src/player/player.ts`의 `play()`:

```ts
// 배속 재생에서는 음성을 끈다 (피치가 틀어지는 것보다 무음이 낫다).
if (this.speed === 1) {
  await this.audio.start(this.positionMs);
}
```

그리고 재생 루프도 1배속일 때만 오디오를 마스터 클럭으로 씁니다.

```ts
const audioMs = this.speed === 1 ? this.audio.currentMs() : null;
```

제가 "음높이가 틀어진 소리보다 무음이 낫다"고 판단해 넣은 것인데,
**블랙박스는 음성이 증거인 경우가 많습니다.** 판단이 틀렸습니다.

### 구조상 필요한 변경 (어느 안을 골라도 공통)

지금 오디오 스케줄러는 "미디어 시각 → AudioContext 시각"을 1:1로 놓고 있습니다.
배속이 붙으면 그 대응이 깨지므로 세 군데를 배속으로 나눠야 합니다.

| 위치 | 지금 | 배속 반영 후 |
|---|---|---|
| 예약 시점 | `originCtx + (segStart - originMs)/1000` | `… /1000/speed` |
| 현재 위치 | `originMs + (ctx.currentTime - originCtx)*1000` | `… *1000*speed` |
| 마스터 클럭 | 1배속만 오디오 | 항상 오디오 |

### 선택지

| 안 | 방식 | 음높이 | 작업량 | 위험 |
|---|---|---|---|---|
| **①** | `AudioBufferSourceNode.playbackRate = speed` | **바뀜** (0.5x 저음 / 4x 다람쥐) | 약 40줄 | 낮음 |
| **②** | 기존 스케줄러 안에서 **WSOLA 시간 신축** | 유지 | 약 120줄 + 테스트 | 중간(품질 튜닝) |
| **③** | PCM을 WAV로 만들어 `<audio preservesPitch>` | 유지 | 중간 | **높음** (마스터 클럭 교체) |

**③이 되는지 이 컨테이너의 Chromium으로 직접 재봤습니다.**
8kHz mono 300Hz 사인파를 WAV로 만들어 `MediaElementAudioSourceNode`로 물리고
`AnalyserNode`로 RMS를 쟀습니다.

```
preservesPitch 지원 : true   (webkitPreservesPitch 불필요)
0.5x rms 0.4325 · 1x 0.4307 · 2x 0.4303 · 4x 0.4315 · 8x 0.4184
```

즉 **0.5x~8x 전 구간에서 음높이를 유지한 채로 소리가 납니다.**
기술적으로는 ③이 가장 품질이 좋습니다.

그런데 ③은 **A/V 동기의 기준을 `AudioContext.currentTime`(샘플 정확)에서
`HTMLMediaElement.currentTime`(거칠고 튐)으로 바꿔야** 합니다.
직전까지 끊김·동기 문제로 고생한 부분을 다시 건드리는 셈이라 위험이 큽니다.

> **권장: ②.** 검증된 클럭 구조를 그대로 두고 음높이도 지킵니다.
> 8kHz 모노 음성은 WSOLA가 가장 잘 맞는 신호입니다.
> 품질이 기대에 못 미치면 ①로 내려앉는 것도 코드 한 줄입니다(신축 함수만 끔).

## 2. 구간 선택이 어렵다

### 원인 세 가지 — 전부 재현했습니다

**(1) 구간 폭이 물리적으로 손가락보다 작습니다.**

한 운행에 파일 60개, 빈 구간 5개면
빈 구간 몫 10% · 구간 몫 90% → **구간 하나가 1.5%**입니다.

| 화면 | 구간 하나의 폭 |
|---|---|
| 데스크톱 1280px | 19px |
| 폰 390px | **5.9px** |

게다가 `segments.ts`의 최소 폭이 `Math.max(0.25, …)`인데 이건 **퍼센트**라
390px에서 0.25% = **0.98px**입니다. 사실상 못 누릅니다.
(권장 터치 표적은 44px입니다. 지금은 1/7 수준입니다.)

**(2) 길게 누르면 바탕색이 변합니다.**
`.strip-track`에 `-webkit-tap-highlight-color`·`user-select`·`touch-action`이
없어서, 안드로이드의 길게 누르기 = 텍스트 선택/탭 하이라이트가 그대로 뜹니다.
(버튼 쪽은 직전 커밋에서 껐지만 스트립은 빠져 있었습니다.)

**(3) 눌렀는지 아닌지 알 수 없습니다.**
클릭 → `seek()` → 다른 파일이면 **파싱·디코더 재설정에 수백 ms**가 걸립니다.
그 사이 커서는 그대로고 스트립에는 아무 표시가 없습니다.
`ch0-note`에 "여는 중…"이 뜨지만 **손가락이 있는 곳에서 멀어** 눈에 안 들어옵니다.

### 고칠 것

즉시 반영(결정 불필요):

- `touch-action: none` · `user-select: none` · 탭 하이라이트 제거
- 트랙 높이 26px → **44px**(터치), 데스크톱은 32px
- 최소 구간 폭을 퍼센트가 아니라 **픽셀(6px)** 로 보장
- 빈 구간을 누르면 **가장 가까운 구간 시작으로 스냅** (지금은 공백 한가운데로 감)
- `pointerdown` 즉시 커서를 옮긴다 (낙관적 반영 — "눌렸다"를 0ms에 보여줌)
- 여는 중인 구간은 스트립에서 **맥동(pulse) 표시**, 끝나면 해제

여기에 더해 조작 방식을 골라야 합니다.

### D10 — 구간 선택 방식

| 안 | 내용 | 작업량 |
|---|---|---|
| **㉮ 드래그 + 말풍선** | 손가락을 끌면 위에 `14:32:05 · 00000460.jdr · 3/60` 말풍선이 따라다니고, 떼는 순간 이동. 5.9px짜리 구간도 **보면서** 맞출 수 있음 | 중간 |
| **㉯ 드래그 + 말풍선 + 2단 확대** | ㉮ + 스트립을 두 줄로: 위는 운행 전체, 아래는 **커서 주변 ±10분 확대**. 확대 줄에서는 구간 하나가 30px 이상 | 큼 |
| **㉰ 위 기본 수정만** | 44px·스냅·맥동만. 드래그 없음 | 작음 |

> **권장: ㉮.** 말풍선이 붙으면 폭 문제는 "정확히 누르기"에서
> "보면서 맞추기"로 성격이 바뀝니다. ㉯의 확대 줄은 파일이 수백 개인
> 운행에서만 의미가 있어, ㉮를 쓴 뒤 필요하면 덧붙이는 편이 낫습니다.

### D11 — 이동 확정 시 진동 피드백 (`navigator.vibrate(10)`)

안드로이드 크롬에서 동작합니다. 손가락이 스트립을 가려도 "걸렸다"를 알 수 있습니다.
데스크톱·iOS에서는 조용히 무시됩니다. **넣을지 말지**만 정해 주세요.

## 3. 즐겨찾기

### 무엇을 저장하는가

증거 추적성 원칙상 **"그 시점이 어느 파일의 몇 초인지"** 가 남아야 합니다.

```
{ absMs, dayKey, path, name, relMs, label, createdAt }
```

`absMs`(절대 벽시계)만으로도 찾아갈 수 있지만, 폴더 구성이 바뀌었을 때
되짚으려면 파일명·파일 내 오프셋이 함께 있어야 합니다.

### 어디에 두는가 — D12

| 안 | 이식성 | 비고 |
|---|---|---|
| **㉮ IndexedDB만** | 이 브라우저 안에서만 | 가장 간단. 데이터 지우면 사라짐 |
| **㉯ IndexedDB + `jdr-bookmarks.json` 저장/불러오기** | 기기·브라우저 넘김 | 인덱스 파일과 같은 방식. **권장** |
| **㉰ 인덱스 파일 안에 같이** | 인덱스와 한 몸 | 인덱스는 폴더 사실의 기록인데 개인 메모가 섞임. 비권장 |

> **권장: ㉯.** 인덱스 파일에서 이미 검증된 방식이고, 즐겨찾기는
> "이 구간 다시 봐야 함" 같은 **작업 기록**이라 기기를 넘길 값어치가 있습니다.

### 화면

요청대로 **창 우측 상단에 별**을 둡니다. 다만 별 하나에 두 가지 일
(추가 / 목록 열기)을 겹치면 헷갈리므로 나눕니다.

```
상단바      … [★ 3]          ← 누르면 즐겨찾기 목록 패널
재생 컨트롤  ⏮ ⟲10 ▶ 10⟳ ⏭ [탐색바] 0:12/1:09 [1x] 🔊 [☆]
                                                      └ 현재 지점 추가/해제
```

- 상단바 `★`에는 **개수 배지**. 목록에서 항목을 누르면 바로 그 지점으로 갑니다.
- **다른 날짜의 즐겨찾기도 바로 갑니다.** 현재 세션 밖이면 그 날짜·운행을
  자동으로 열고 해당 시각으로 이동합니다 (이미 `folderState`에 전체 목록이 있음).
- 현재 재생 위치가 즐겨찾기 지점 ±2초 안이면 컨트롤의 별이 **★로 채워집니다.**
- 이름은 기본 `09-08 14:32:05`, 목록에서 수정 가능.
- 파일 하나만 연 모드에서도 동작합니다(그때는 `dayKey`가 빔).

### 썸네일은 넣지 않겠습니다

캔버스를 JPEG로 굽으면 항목당 8~15KB입니다. 100개면 1.5MB이고
`jdr-bookmarks.json`에 base64로 들어가면 2MB가 됩니다.
목록에 시각·파일명·길이가 있으면 식별에 충분하다고 봅니다.
**필요하다고 하시면 넣겠습니다.**

## 결정 결과 및 구현 (D9 ② · D10 ㉮ · D11 넣기 · D12 ㉯)

### 1. 배속 음성 — `core/timestretch.ts`

SOLA 계열 신축기를 넣었습니다. 겹침 128표본(16ms), 탐색 ±96표본(±12ms).
1배속일 때는 신축기를 아예 거치지 않아 완전 무손실입니다.

검증은 **영점 교차 횟수**로 했습니다. 사인파의 영점 교차는 초당 2f회이므로
음높이가 바뀌면 곧바로 드러납니다.

| 300Hz 사인, 3초 | 영점 교차 비율 |
|---|---|
| 표본 재생(`playbackRate`) 2배속 | **2.0배** (음높이가 올라감) |
| 시간 신축 2배속 | **1.0배** (유지) |

500ms 조각으로 끊어 넣어도 통째로 넣은 것과 길이가 같고, 조각 경계에서
표본 간 급변이 0.5를 넘지 않는 것(= "딱" 소리가 없는 것)까지 확인했습니다.

e2e에서는 `AudioBufferSourceNode.start`를 가로채 예약된 버퍼를 셌습니다.

| 배속 | 조각 하나의 실제 길이 |
|---|---|
| 1x | 0.5초 |
| 2x | 0.25초 |
| 0.5x | 1.0초 |

미디어 500ms가 배속만큼 짧게 나간다는 뜻입니다. 표본을 다시 뽑는 방식이었다면
길이가 0.5초 그대로이고 음높이만 올라갔을 것입니다.

### 2. 구간 선택

- 최소 구간 폭을 **픽셀 기준 7px**로. 다 줄 수 없을 만큼 좁으면 구간 몫을
  똑같이 나눕니다(빈 구간 표시는 유지)
- 끌면 손가락 위에 `14:32:05 / 00000460.jdr · 3/60` 말풍선
- 끄는 동안에는 커서만 옮기고 **뗄 때** 이동 — 끄는 내내 파싱이 걸리지 않습니다
- 확정되면 `navigator.vibrate(10)`
- 빈 구간을 누르면 가까운 구간의 시작/끝으로 스냅
- 트랙 높이 터치 44px / 마우스 32px, `touch-action: none`, `user-select: none`
- 여는 중인 구간은 스트립에서 맥동

### 3. 즐겨찾기

- 상단바 `★ n` → 목록 패널. 항목을 누르면 그 지점으로 바로 이동하며,
  **다른 날짜면 그 날짜·운행을 자동으로 엽니다**
- 컨트롤의 `☆` → 현재 지점 담기/빼기. 지점 위에 있으면 `★`로 채워집니다
- 같은 장면을 두 번 눌러도 하나입니다(1초로 뭉뚱그린 `경로@초`가 키)
- 저장 항목: `absMs · dayKey · path · name · relMs · label · createdAt`
  — 절대 시각만으로는 폴더 구성이 바뀌었을 때 되짚을 수 없습니다
- IndexedDB(`jdr-viewer-bookmarks`)에 자동 저장 + `jdr-bookmarks.json` 저장/불러오기
- 불러오기는 **합치기**이며, 같은 지점이면 원래 이름을 지킵니다
- 브라우저 저장을 못 쓰는 환경(시크릿·file://)에서는 패널에서 알리고 파일 저장을 권합니다

썸네일은 넣지 않았습니다(계획안 사유 그대로).
