# 화면 설계 개편 계획안

## 0. 무엇을 베낄 것인가 — 겉모습이 아니다

Apple과 Linear을 조사한 결론부터. **둘의 공통점은 "예쁜 스타일"이 아니라
`규칙을 하나로 통일하고 예외를 없앤 것`** 이다.

| | Apple | Linear | 우리가 가져올 것 |
| --- | --- | --- | --- |
| 간격 | 8px 기본, 미세조정만 2·4·6 | 8px 기본 스케일 | **8px 그리드 하나로 통일** |
| 타이포 | 큰 글자는 `clamp()` 유동, 본문은 단계 고정 | Inter 한 벌, 굵기로만 계층 | **크기 5단계 + 굵기 3단계로 끝** |
| 색 | 의미별 토큰, 강조색 최소 | 2025년 개편에서 **색을 더 줄임** | **강조색 1개**, 나머지는 회색조 |
| 밀도 | 여백 넉넉 | 정보 밀도 높되 행간·자간으로 읽힘 | **감사 도구 = Linear 쪽**에 가깝게 |
| 터치 | **최소 44×44pt** | — | 지금 40px인 버튼들을 올린다 |

우리 앱은 마케팅 사이트가 아니라 **현장에서 한 손으로 쓰는 감사 도구**다.
그래서 Apple의 "여백의 미"보다 **Linear의 "빽빽하지만 읽히는" 밀도**가 맞다.
다만 터치 규격과 8px 그리드는 Apple 쪽을 따른다.

## 1. 지금 화면의 문제 — 추측이 아니라 이번 작업에서 실제로 겪은 것

**① 맥락이 스크롤과 함께 사라진다 (가장 큰 문제)**

바로 앞 요청이 증거다. 내보내기 칸에서 구간을 고르는데 재생 위치가 화면 밖에
있었다. 나는 **벽시계를 한 벌 더 그려 넣어** 막았다. 증상을 가린 것이지 원인을
고친 게 아니다. 원인은 **영상·컨트롤·띠·패널이 전부 한 줄기 스크롤에 얹혀
있다**는 구조다. 같은 문제가 지도·센서·대화 탭에서도 그대로 난다.

**② 세로가 너무 길다**

390×844 화면에서 영상 두 칸(16:9 두 개)만 440px다. 화면의 절반을 넘게 쓰는데,
정작 후방 영상은 대개 곁눈질 대상이다. 그 아래로 컨트롤·출처·운행칩·띠·기록시각이
쌓여 **탭에 닿기도 전에 한 화면을 다 쓴다.**

**③ 탭 6개가 가로로 밀린다**

`요약·구간·지도·센서·대화·내보내기`가 좁은 폭에서 가로 스크롤이 된다.
지금 어느 탭인지, 무슨 탭이 더 있는지 한눈에 안 보인다.

**④ 터치 규격 미달**

```css
.controls .btn-icon { min-width: 40px; padding: 7px 6px; }
```
40px다. 권장은 44px. 버튼 8개가 붙어 있어 오조작이 난다.

**⑤ 글자 계층이 없다**

13~14px 회색 글씨가 화면을 덮는다. **제일 중요한 숫자와 그냥 참고 정보가 같은
크기**다. 벽시계를 키워 달라는 요청이 그래서 나왔다.

**⑥ 값이 흩어져 있다**

`styles.css` 605줄에 6·7·8·9·10·12·14·18·20px이 손으로 박혀 있다.
고칠 때마다 어디를 맞춰야 할지 매번 다시 판단해야 한다.

**⑦ 가로 모드를 안 쓴다**

블랙박스 영상은 16:9다. 폰을 눕히면 영상이 두 배로 커지는데 레이아웃이 그대로다.

## 2. 제안하는 뼈대 — "앱 셸"

핵심 한 줄: **영상·컨트롤·벽시계·띠는 고정, 그 아래 패널만 스크롤.**

```
┌─────────────────────────┐  ← 상단: 브랜드 + 날짜/폴더/파일   (고정)
├─────────────────────────┤
│      전방 영상 (16:9)    │  ← 무대: 영상 + 컨트롤 + 벽시계 + 띠
│           [후방 PIP]     │     (고정, 화면의 45% 안쪽)
│  ⏮ ⟲10 ▶ 10⟳ ⏭         │
│  08:26:25  0:02.8/0:48.4 │
│  ▓▓▓▓▓│▓▓▓▓▓▓▓▓▓▓       │
├─────────────────────────┤
│                         │
│   패널 (여기만 스크롤)    │  ← 요약/구간/지도/센서/대화/내보내기
│                         │
├─────────────────────────┤
│  요약 구간 지도 … 내보내기 │  ← 하단 탭바 (고정, 엄지 닿는 자리)
└─────────────────────────┘
```

이 구조가 ①②③⑦을 한꺼번에 푼다.

- 내보내기 구간을 고르는 내내 **벽시계와 띠가 눈앞에 있다** → 중복 표시가 필요 없어진다
- 탭이 **엄지 닿는 아래쪽**에 고정되어 6개가 한 줄에 다 보인다
- 패널만 스크롤하므로 **긴 구간 목록을 봐도 영상을 잃지 않는다**
- 폰을 눕히면 무대와 패널이 **좌우로** 갈라진다 (데스크톱과 같은 규칙)

### 주의 — 이 구조의 함정

모바일 브라우저 주소창이 스크롤에 따라 나타났다 사라지며 높이가 출렁인다.
`100vh`는 거짓말을 하고, `dvh`는 스크롤할 때마다 레이아웃이 튄다.
**고정 요소가 있는 화면에는 `svh`(항상 보이는 최소 높이)가 안전하다.**
여기에 `env(safe-area-inset-bottom)`을 더해 제스처 바에 가리지 않게 한다.
갤럭시 실기기에서 반드시 확인해야 하는 부분이다 (개발자도구로는 재현 안 됨).

## 3. 디자인 토큰 — 값을 손으로 박지 않는다

```css
:root {
  /* 간격 — 8px 그리드. 4는 미세조정용 */
  --s-1: 4px;  --s-2: 8px;  --s-3: 12px; --s-4: 16px;
  --s-5: 24px; --s-6: 32px; --s-7: 48px;

  /* 글자 — 5단계로 끝낸다 */
  --t-display: clamp(20px, 4.2vw, 28px);  /* 벽시계처럼 "지금 제일 중요한 값" */
  --t-title:   17px;   /* 구획 제목 */
  --t-body:    15px;   /* 본문 */
  --t-label:   13px;   /* 라벨·보조 */
  --t-micro:   12px;   /* 각주 */

  /* 굵기 3단계: 400 본문 / 600 강조 / 700 제목 */
  /* 한글은 라틴보다 글자속이 좁아 행간을 더 준다 */
  --lh-tight: 1.3;  --lh-body: 1.6;

  --tap: 44px;  /* 터치 최소 규격 */
}
```

숫자는 전부 `font-variant-numeric: tabular-nums` — 시각·좌표·용량이 흔들리지
않아야 눈으로 대조할 수 있다. (감사 도구에서 이게 생각보다 크다.)

## 4. 단계 — 되돌릴 수 있게 쪼갠다

| 단계 | 내용 | 위험 | 확인 |
| --- | --- | --- | --- |
| **1** | 토큰 도입 + 기존 값 치환 (보이는 변화 최소) | 낮음 | 기존 e2e 59개 그대로 통과 |
| **2** | 타이포 계층 + 터치 44px + 컨트롤 재배치 | 낮음 | 버튼 크기 e2e 추가 |
| **3** | **앱 셸 전환** (고정 무대 + 하단 탭바) | **중간** | 실기기 확인 필수 |
| **4** | 전/후방 PIP, 가로 모드 | 중간 | 실기기 확인 |
| **5** | 중복 표시 제거 (벽시계 한 벌로) | 낮음 | e2e 수정 |

각 단계는 따로 커밋한다. 3단계가 실기기에서 어색하면 **거기서 멈춰도 1·2단계
이득은 남는다.**

## 5. 건드리지 않는 것

- **기능·동작은 그대로.** 이번 작업은 배치와 표기만 바꾼다.
- 단일 HTML 파일, `file://` 구동, 오프라인 — 전부 유지.
- 기존 e2e 59개는 선택자를 바꿔야 할 수 있으나 **검증 내용은 줄이지 않는다.**
