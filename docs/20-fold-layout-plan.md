# 폴드형 화면 대응 계획안 — 사라지는 탭바와 영상 아래 검은 여백

## 0. 먼저 기기 규격을 확인했다

| | 해상도 | **CSS 뷰포트** | 비율 |
| --- | --- | --- | --- |
| Fold 7 **메인**(펼침) | 1968×2184 | **984×1092** (DPR 2.0) | 약 1:1.11 (거의 정사각) |
| Fold 7 **커버**(접음) | 1080×2520 | 약 412×915 | 21:9 (아주 길쭉) |

핵심은 **메인 화면 폭이 984px**라는 점이다. 지금 좌우 분할 기준이 `900px 이상`
이라 **세로로 들고 있어도 좌우로 갈린다.** 거의 정사각이라 "가로냐 세로냐"로
판단하는 규칙이 통하지 않는다.

## 1. 측정 — 일곱 가지 크기에서 재 봤다

| 화면 | 배치 | **탭바** | **패널 높이** | 영상 칸 | **칸 안 검은 여백** |
| --- | --- | --- | --- | --- | --- |
| 984×1092 (메인 세로) | 좌우 | 보임 | 965 | 253×717 | **575px** |
| 1092×984 (메인 가로) | 좌우 | 보임 | 857 | 307×609 | **436px** |
| 984×860 (주소창 포함) | 좌우 | 보임 | 733 | 253×485 | **343px** |
| 412×915 (커버) | 세로 | 보임 | 264 | 380×215 | 0 |
| **412×620** (커버·짧음) | 세로 | **안 보임** | **0** | 380×186 | 0 |
| 344×882 (옛 커버) | 세로 | 보임 | 269 | 312×176 | 0 |
| 700×390 (좁은 가로) | 좌우 | 보임 | 263 | 111×129 | 0 |

여기서 **세 가지**가 드러난다.

## 2. 문제 ① — 화면이 짧으면 탭바가 사라지고 스크롤도 안 된다

**412×620에서 패널 높이가 0이고 탭바가 화면 밖으로 2px 나간다.** 요약·구간·
지도에 닿을 방법이 없다. 보고해 주신 그대로다.

원인은 내가 한 선택에 있다. 앞서 패널의 긴 내용이 무대를 눌러 컨트롤과 띠가
잘리는 걸 막으려고 **무대를 아예 안 줄어들게** 못박았다.

```css
.stage { flex: 0 0 auto; }   /* 줄지 않는다 */
```

그랬더니 화면이 짧을 때 **패널 몫이 0**이 된다. 몸통은 지켰는데 머리가
잘린 셈이다.

**고칠 방향**: 줄어드는 쪽을 **영상 한 곳으로 못박는다.**
- 무대는 줄어들 수 있게 하되(`flex: 0 1 auto`)
- 그 안에서 **영상만** 양보하고(`flex: 0 1 auto` + `min-height: 0`)
- 컨트롤·띠는 끝까지 고정(`flex: 0 0 auto`)
- 패널에는 **최소 높이**를 줘서 탭바가 절대 밀려나지 않게 한다

이러면 짧은 화면에서 영상이 작아질 뿐, 조작과 탭은 늘 남는다.

## 3. 문제 ② — 영상 아래 검은 여백 (지적하신 그것)

**메인 세로에서 영상 칸은 253×717인데 실제 그림은 253×142다.** 칸마다
**575px이 검정**이다. 두 칸이니 화면의 상당 부분이 까맣게 낭비된다.

원인은 두 줄이다.

```css
.video-grid { flex: 1 1 auto; }              /* 칸이 남는 높이를 다 채운다 */
.video-cell canvas { height: 100%; }         /* 그림은 16:9를 지킨다 */
```

칸은 늘어나는데 그림은 비율을 지키니, **그 차이가 검은 배경으로 남는다.**
(검은 건 영상이 아니라 칸의 배경색이다.)

**고칠 방향**: 칸이 그림보다 커지지 않게 한다. 폭과 높이 중 **작은 쪽에 맞춰**
16:9 그대로 줄인다.

```css
.video-cell canvas {
  width: min(100%, calc(var(--video-h) * 16 / 9));
  height: auto;
  aspect-ratio: 16 / 9;
}
```

폭이 넉넉하면 높이가, 높이가 모자라면 폭이 먼저 줄어든다. **어느 쪽이든
검은 여백은 0이 된다.**

## 4. 문제 ③ — 측정하다 발견: 폴드 메인에서 영상이 너무 작다

같은 줄을 다시 보자. **메인 세로에서 영상 한 칸이 253px**밖에 안 된다.
984px 화면에서 좌우로 갈리고(무대 약 530px), 그 무대를 영상 두 칸이 또
나눠 가지기 때문이다. 8인치 화면을 쓰면서 영상은 엄지손톱만 하다.

**원인은 "무엇을 기준으로 배치를 정하느냐"에 있다.** 지금은 **화면 폭**으로
정한다. 그런데 정작 영상이 놓이는 곳은 **무대 열**이고, 그 폭은 화면 폭과
다르다(984 → 530).

**고칠 방향**: 배치를 **무대 자신의 폭**으로 정한다 (CSS 컨테이너 쿼리).
- 무대가 넓으면 → 전방·후방 나란히
- 무대가 좁으면 → 전방 크게 + 후방 PIP

그러면 메인 세로에서 전방이 530px 폭을 다 써서 **253 → 530px**, 높이도
142 → 298px로 커진다.

## 5. 결정이 필요한 것

1. 화면이 짧을 때 무엇을 양보할지
2. 검은 여백을 없애는 방식
3. 폴드 메인(984px 세로)에서의 배치
4. 영상에 줄 최대 높이

## 6. 범위

- **인덱스·파싱·재생 로직은 건드리지 않는다.** 배치와 크기만 바꾼다.
- 기존 e2e 63개는 그대로 통과해야 한다.

## 만들며 걸린 것 세 가지

**① "무대를 줄이자"가 오히려 화면을 부쉈다.**
무대를 줄어들게 했더니 패널이 `flex-basis: auto`로 **자기 내용 높이만큼**
공간을 요구해 무대가 비율대로 눌렸다. 영상이 2px로 찌그러지고 패널 위로
겹쳐 그려졌다. → 패널의 basis를 0으로 두고(어차피 안에서 스크롤한다),
무대는 줄이지 않는 대신 **`--video-h`로 애초에 넘치지 않게 예산을 잡았다.**
줄이는 것보다 안 넘치게 하는 쪽이 확실하다.

**② 커스텀 속성을 선택자 없이 썼다.**
미디어쿼리 안에 `--video-h: …`만 덜렁 넣었더니 **통째로 무시**됐다.
측정값이 안 바뀌어서 알았다. `.stage`에 걸어 해결.

**③ 344px에서 가로 스크롤이 생겼다.**
상단바 버튼 넉 장이 안 들어갔다. 손가락 규격(44px)을 깎는 대신 제목 글자를
접고(브라우저 탭에 있다), 컨트롤은 줄을 바꾸고, 탭 여섯 개는 폭을 고르게
나눠 **한눈에 다 들어오게** 했다.

## 정직하게 남길 것

커버 화면(412px)에서 영상은 **폭에 묶여** 213px이 한계다. 16:9라 폭이
412px이면 높이는 232px을 넘을 수 없다. "화면의 45%"는 **넓거나 짧은 화면에서만**
실제로 작동하는 상한이다 — 좁은 폰에서는 애초에 폭이 먼저 걸린다.
