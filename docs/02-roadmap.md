# 개발 로드맵 (제안)

`docs/01-android-knowledge.md` 검토 결과를 바탕으로 한 단계별 계획입니다.
각 단계는 **그 자체로 동작하는 결과물**이 나오도록 잘랐습니다.

---

## 단계 0 — 파서 먼저 (안드로이드 없이 가능)

**목표**: JDR을 정확히 읽는 순수 Kotlin/JVM 모듈

- [ ] `:core-jdr` 순수 JVM 모듈 (안드로이드 의존성 0)
- [ ] `SeekableSource` 인터페이스 (파일/URI 구현을 나중에 갈아끼움)
- [ ] JEB 블록 탐색 + 5가지 검증 조건
- [ ] 패킷 순차 파싱 + 인덱스 테이블 대조
- [ ] GPS / G센서 레코드 디코딩 (NMEA 변환 포함)
- [ ] `PacketTable` SoA 구조로 메모리 최적화
- [ ] SHA-256 스트리밍 계산
- [ ] JUnit 테스트 + 합성 골든 JDR 생성기
- [ ] **검증**: Python 도구 출력과 1:1 대조

> 이 단계는 Android SDK가 없어도 되므로 현재 컨테이너에서 바로 착수 가능합니다.

## 단계 1 — MVP 앱 (변환 중심)

**목표**: 폰에서 JDR을 열어 요약을 보고 MP4로 내보내기

- [ ] Compose + Material 3 앱 골격, targetSdk 36
- [ ] SAF 파일 열기 + 영구 권한 + 최근 파일
- [ ] 분석 요약 화면 (SHA-256, 블록/패킷/시간/태그/불일치)
- [ ] `MediaMuxer` + AAC 인코더로 MP4 내보내기 (전/후방)
- [ ] WAV / GPS CSV / G센서 CSV 내보내기
- [ ] WorkManager 백그라운드 변환 + 진행률 알림
- [ ] 변환된 MP4를 Media3 ExoPlayer로 재생

## 단계 2 — 네이티브 재생

**목표**: 변환 없이 즉시 재생

- [ ] Annex-B NAL 파서 (start code, nal_unit_type)
- [ ] SPS 파싱으로 해상도 획득 (또는 `INFO_OUTPUT_FORMAT_CHANGED` 활용)
- [ ] `MediaCodec` 비동기 모드 디코더 + `SurfaceView`
- [ ] `AudioTrack` PCM 재생 + **무음 갭 채우기**
- [ ] 오디오 마스터 클럭 기반 A/V 동기
- [ ] I-프레임 인덱스 기반 시크, 배속, 프레임 단위 이동
- [ ] 전/후방 2채널 동시 재생 + 단일 채널 폴백

## 단계 3 — 데이터 시각화

## 먼저 결정해야 할 사항

| 질문 | 왜 중요한가 |
|---|---|
| 최소 지원 안드로이드 버전 | minSdk 26 vs 24 — desugaring 필요 여부가 갈림 |
| Play 스토어 출시 vs 사내 배포 | 출시라면 정책·개인정보 문서 작업이 추가됨 |
| 지도 온라인 타일 허용 여부 | 완전 오프라인이면 타일 번들링 설계가 필요 |
| 다른 IROAD 기종 JDR 샘플 확보 가능 여부 | 포맷 일반화 범위를 결정 |
| 증거 용도 요구 수준 | 해시 체인·감사 로그 등 추가 요건 발생 가능 |
