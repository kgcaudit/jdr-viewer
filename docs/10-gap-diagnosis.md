# 빈 구간이 왜 끊겨 보이는가

실기기 화면에서 22개 구간 사이가 전부 빗금으로 끊겨 보이는 문제입니다.
**두 가지가 섞여 있었습니다.**

---

## 1. 빗금이 실제 공백보다 훨씬 넓게 그려지고 있었습니다

예전 축 계산은 **빈 구간 하나에 무조건 2%**를 줬습니다. 길이와 무관하게요.

```
21곳 × 2% = 42% → 상한 30%로 잘림
```

그래서 **5초짜리 공백 21개가 화면의 30%를 덮었습니다.** 실제로 비어 있는
시간은 7%인데도요. "영상이 온통 끊겼다"로 보이는 건 당연합니다.

### 실제 길이에 비례하게 바꿨습니다

```
빈 구간 몫 = 실제로 빈 시간 / 전체 시간     (30% 상한은 유지)
각 구간 폭 = 그 몫을 길이 비율로 나눔        (하나 최대 6%)
최소 폭    = 2px                             (있다는 사실은 숨기지 않음)
```

측정(22개 파일·30분 운행):

| 파일 사이 공백 | 예전 빗금 비율 | 지금 |
|---|---|---|
| 5초씩 | 30% | **약 7%** (실제와 같음) |
| 60초씩 | 30% | 그보다 2배 이상 넓게 |
| 13시간 1곳 | 30% | 30% (상한 유지 — 안 그러면 영상이 안 보임) |

30%는 **13시간짜리 주차 공백** 같은 걸 위한 상한이었는데,
몇 초짜리에도 똑같이 적용되고 있었던 것입니다.

---

## 2. "왜 비었는지"를 말해 주지 않았습니다

빈 구간에는 성격이 다른 두 가지가 섞여 있습니다.

| | 뜻 | 대응 |
|---|---|---|
| **파일 번호가 건너뜀** (`87 → 89`) | 그 파일이 **실제로 없다** (덮어쓰기·삭제) | 복구 불가 |
| **번호가 이어짐** (`87 → 88`) | 파일은 다 있는데 기록이 끊겼거나 시각이 어긋난 것 | 원인 조사 |

앱은 이걸 구분하지 않고 똑같은 빗금만 그렸습니다.

### 이제 밝힙니다

- **요약** 탭: `빈 구간 21곳 · 합계 6:01 / 파일 5개 없음`
- **구간** 탭: 빈 구간마다 한 줄로

```
23:20:11 ~ 23:20:28   17초   파일 1개 없음 (00000087.jdr → 00000089.jdr)
23:21:35 ~ 23:21:40    5초   파일 번호는 이어짐 (00000089.jdr → 00000090.jdr) — 기록 끊김
```

- 파일이 없는 쪽은 왼쪽에 주황 띠를 둡니다
- 스트립의 빗금을 길게 누르면 같은 내용이 툴팁으로 뜹니다

**이걸 보시면 파일 누락인지 아닌지가 바로 갈립니다.**

---

## 3. 덤으로 찾은 진짜 버그 — 시작 시각의 기준

내보내기·재생 쪽을 훑다가 발견했습니다. 이건 표시 문제가 아니라 계산 오류입니다.

- 구간의 **끝** 시각: 헤더와 마지막 패킷을 대조해 **늦은 쪽**을 씀 (지난번에 고침)
- 구간의 **시작** 시각: **헤더만** 씀 ← 대조를 안 하고 있었습니다

헤더의 시작 시각이 실제 첫 패킷보다 늦으면 **그 차이만큼 없는 빈 구간이
생기고**, 이르면 **없는 겹침이 생깁니다.** 지난번에 종료 시각에서 1.8초
차이를 확인했으니, 시작 시각도 어긋날 수 있다고 봐야 했습니다.

게다가 재생은 `doc.firstTimeMs`(실제 첫 패킷)부터 시작하는데 타임라인의
절대 시각은 헤더 기준이었습니다. **둘이 어긋나면 타임라인 전체가 밀립니다.**

### 고친 것

- 구간 시작을 **실제 첫 패킷** 기준으로 통일 (재생 기준과 같아짐)
- 재생의 절대 시각도 `doc.firstTimeMs`를 기준으로 (양쪽이 같은 값을 씀)
- 어긋난 양을 `headerShiftMs`로 기록해, 0.5초 이상이면 구간 목록에
  `헤더 시각 7.0초 어긋남`으로 표시
- 계산이 바뀌었으므로 **인덱스 v2와 기존 브라우저 캐시는 버립니다**
  (`jdr-index.json`을 다시 저장해 주세요)

## 아직 모르는 것

**실제 파일이 없어 원인을 확정하지 못했습니다.** 위 셋 중
어느 것이 주된 원인인지는 새 빌드의 **구간 탭**을 보시면 바로 압니다.

- `파일 N개 없음`이 대부분이면 → 파일 누락이 맞습니다 (앱은 사실대로 그린 것)
- `번호는 이어짐`이 대부분이면 → 기록이 끊긴 것이고, 옆에 뜨는
  `헤더 시각 N초 어긋남`이 그 원인을 짚어 줍니다

그 화면을 알려 주시면 다음 판단을 하겠습니다.
