# JDR Viewer — 웹 프로토타입

IROAD 블랙박스 `.jdr` 파일을 **브라우저에서 바로** 열어보는 뷰어입니다.
파일은 **서버로 전송되지 않고** 전부 브라우저 안에서 처리됩니다.

## 실행

```bash
cd web
npm install
npm run dev        # http://127.0.0.1:5173
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 정적 빌드 (`dist/`) — 아무 정적 호스팅에나 올리면 됨 |
| `npm run build:single` | **단일 HTML 빌드** (`dist-single/index.html`) — 파일 하나로 끝, 더블클릭해서 열면 됨 |
| `npm run make-sample -- out.jdr --mb 150` | 테스트용 합성 JDR 생성 |
| `npm run typecheck` | 타입 검사 |
| `npm test` | 파서 유닛 테스트 (vitest, 22개) |
| `npm run test:e2e` | 브라우저 E2E 테스트 (Playwright, 8개) |

## 단일 HTML로 쓰기

`npm run build:single` 로 만든 `dist-single/index.html` 하나면 됩니다.
JS·CSS·워커·이미지가 전부 안에 들어 있어 **더블클릭해서 열면 바로 동작**합니다.

`file://`로 직접 열면 브라우저가 Web Worker 생성을 막기 때문에
**메인 스레드 파싱으로 자동 폴백**합니다. 150MB 파일로 측정한 결과 속도 차이는 거의 없습니다
(파싱이 CPU가 아니라 파일 읽기에 묶여 있기 때문).

| 방식 | 150MB 파싱 | JS 힙 |
|---|---|---|
| 로컬 서버 (워커) | 4.9초 | 7MB |
| `file://` (메인 스레드) | 4.9초 | 48MB |

파일 전체를 메모리에 올리지 않으므로 힙 사용량이 파일 크기와 무관합니다.

## 구현된 기능

- **파일 열기 / 폴더 열기** — `<input type="file">`, `webkitdirectory`, 드래그 앤 드롭(폴더 포함).
  `File.slice()`로 필요한 구간만 읽어 수 GB 파일도 메모리에 올리지 않음
- **날짜 캘린더** — 폴더를 열면 월간 캘린더가 먼저 뜹니다. 날짜를 고르면 그 날짜만 불러옵니다.
  하루 안에서도 공백 10분 이상이면 **운행 단위**로 나눠 보여줍니다
- **폴더 병합 재생** — 파일들을 **기록 시각 순**으로 이어 붙여 재생.
  파일 경계를 넘어 자동 전환(다음 구간 미리 읽기), 빈 구간은 자동 건너뛰기
- **파일 단위 재생 현황** — 슬라이더와 시간 라벨이 **현재 영상 파일 기준**입니다.
  `⏮⏭`는 이전/다음 파일, `⟲10 10⟳`는 10초 뒤/앞(파일 경계를 넘어감)
- **인덱스 파일** — 훑은 결과를 `jdr-index.json`으로 내보내 폴더에 두면, 다음에 열 때
  파일 1개만 읽고 헤더 훑기를 건너뜁니다. 기기·브라우저를 넘어 재사용됩니다
- **프로브 캐시** — 헤더 읽기 결과를 IndexedDB에도 저장 (같은 브라우저 한정)
- **세그먼트 인덱싱** — 헤더 512바이트만 읽어 파일당 1ms. 1000개 파일도 1초 안에 타임라인 완성
- **폴더 선택** — `data`/`event`처럼 같은 시각을 담은 폴더는 나눠서 선택 (겹침 경고)
- **운행 칩** — 재생 화면에서 같은 날짜의 다른 시간대로 바로 이동 (캘린더 경유 불필요)
- **증거 추적성** — 재생 중 현재 프레임의 출처 파일과 구간 번호를 항상 표시
- **파싱** — Web Worker에서 진행률과 함께. JEB 블록 탐색, 패킷 순차 파싱, 12바이트 인덱스 대조
- **무결성** — 스트리밍 SHA-256, 인덱스 불일치 건수 표시
- **영상 재생** — WebCodecs `VideoDecoder`로 전/후방 2채널. 변환 없이 바로 재생
- **음성** — Web Audio로 PCM 8kHz 재생. `AudioContext.currentTime`이 A/V 마스터 클럭
- **시크** — I-프레임(`00VI`) 인덱스 기반. 프레임 단위 이동, 0.5~4배속
- **지도** — Leaflet + OSM. 경로 폴리라인 + 재생 위치 마커 동기화
- **차트** — uPlot 속도/G센서 3축. 재생 위치 커서 동기화
- **내보내기** — 요약 JSON, GPS·G센서·패킷 CSV, WAV, H.264 Annex-B
- **반응형** — 데스크톱 2열 / 모바일 1열 + 탭. 다크 모드

## 구조

```
src/core/      플랫폼 독립 파서 (DOM 의존 없음 → 안드로이드 포팅 시 그대로 번역 가능)
  byte-source  ByteSource 추상화 (Blob / ArrayBuffer) + WindowReader
  parser       JEB 블록·패킷·GPS·G센서 파싱
  nal          H.264 Annex-B NAL 스캔 + SPS 파싱 (해상도/코덱 문자열)
  sha256       스트리밍 SHA-256 (crypto.subtle은 대용량에 못 씀)
  export       CSV / WAV / JSON 생성
src/worker/    파싱 워커
src/player/    WebCodecs 디코더, Web Audio, 재생 엔진
src/ui/        요약·지도·차트·내보내기 패널
```

## 알아둘 점

### 브라우저 지원

| 브라우저 | 영상 재생 |
|---|---|
| Chrome / Edge / Opera 94+ | ✅ |
| Safari 26.0+ (macOS·iOS·iPadOS) | ✅ |
| Firefox 130+ (데스크톱) | ✅ |
| Firefox Android | ❌ WebCodecs 미지원 |

WebCodecs가 없어도 **요약·GPS·센서·내보내기는 전부 동작**합니다. 영상만 비활성화됩니다.

### 코덱 수동 지정

코덱 자동 판별(SPS 파싱)이 실패하는 JDR 변형을 위해 쿼리 파라미터를 지원합니다.

```
?codec=avc1.4D401E
```

### 재생 최적화

프레임마다 파일을 읽으면 69초 영상 하나에 **4,190회**(초당 60회)가 됩니다.
모바일에서는 이 호출 횟수가 그대로 끊김이 되므로 4MB 단위로 버퍼링합니다.

| | 파일 읽기 호출 |
|---|---|
| 버퍼링 전 | 4,190회 |
| 버퍼링 후 | **18회** |

그 외: `optimizeForLatency: false`(파일 재생에는 처리량이 중요),
`hardwareAcceleration: 'prefer-hardware'`, 캔버스 `desynchronized: true`,
화면이 가려지면 자동 일시정지.

끊김을 진단하려면 `?debug=1`로 열면 초당 디코딩·렌더·버린 프레임 수가 표시됩니다.

### 성능 (70MB 실파일 기준 실측)

| 작업 | 1파일 | 읽는 양 | 828파일(58GB) 환산 |
|---|---|---|---|
| 프로브(타임라인) | 1ms | 1KB | 0.8초 |
| GPS·센서 스캔 | 19ms | 0.1MB | 선택한 날짜만 (하루 79개 ≈ 0.4초) |
| 재생용 파싱 | 59ms | 70MB | 구간별 지연 로드 |

680개 폴더 실측:

| 폴더 열기 방식 | 소요 | 실제로 여는 파일 수 |
|---|---|---|
| 최초 (헤더 프로브) | 1.6초 | 680개 |
| 브라우저 캐시 | 0.45초 | 0개 |
| **인덱스 파일** | **0.42초** | **1개 (78.9KB)** |

날짜 열기 0.1초, 그 날짜 GPS 스캔 0.4초, JS 힙 12MB.

전 구간 스캔은 파일을 통째로 파싱하지 않고 **12바이트 인덱스 테이블의 태그**를 보고
GPS·센서 패킷 자리만 골라 읽습니다. 전체 파싱이었다면 828개에 약 28분이 걸립니다.

### 아직 안 한 것

- **여러 구간에 걸친 병합 내보내기** — 현재 내보내기는 재생 중인 구간 하나만 대상
- **MP4 내보내기** — Mediabunny 등 JS 먹서 + `AudioEncoder`(AAC) 필요
- **PWA** — Service Worker / manifest (오프라인·홈 화면 추가)
- **충격 이벤트 자동 검출** — 합성 가속도 임계값 기반 점프
- 파싱이 파일을 두 번 읽음 (해시+스캔 1회, 패킷 헤더 1회). 블록 체인을 따라가는 방식으로 줄일 수 있음

## 면책

JDR 포맷 해석은 샘플 1개에 대한 **역분석 추정**이며 제조사 공식 사양이 아닙니다.
GPS 속도, G센서 스케일(raw ÷ 1024 ≈ g)은 추정값입니다.
원본성 판단의 기준은 **원본 JDR 파일과 SHA-256**이며, 내보낸 결과물은 파생물입니다.
