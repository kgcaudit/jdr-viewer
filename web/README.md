# Movement Analysis System — 웹 앱 <sub>(구 JDR Viewer)</sub>

IROAD 블랙박스 `.jdr` 파일과 휴대폰 위치기록을 **브라우저에서 바로** 열어,
동선을 재구성하고 대조하는 뷰어입니다. 파일은 **서버로 전송되지 않고** 전부
브라우저 안에서 처리됩니다. 라이브: <https://kgcaudit.github.io/jdr-viewer/>

## 실행

```bash
cd web
npm install
npm run dev        # http://127.0.0.1:5173
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 정적 빌드 (`dist/`) — 아무 정적 호스팅에나 올리면 됨 |
| `npm run build:single` | **단일 HTML 빌드** (`dist-single/index.html`) — 파일 하나로 끝, 더블클릭 |
| `npm run make-sample -- out.jdr --mb 150` | 테스트용 합성 JDR 생성 |
| `npm run typecheck` | 타입 검사 |
| `npm test` | 유닛 테스트 (vitest, 314개) |
| `npm run test:e2e` | 브라우저 E2E 테스트 (Playwright, 91개) |

## 배포 (GitHub Pages)

기본 브랜치에 push하면 `.github/workflows/deploy-pages.yml`가 `dist-single`을 빌드해
GitHub Pages로 **자동 배포**합니다. 배포되는 것은 데이터 없는 앱 껍데기 HTML뿐입니다.

> 열어 둔 탭은 **새로고침해야** 새 코드가 반영됩니다(탭에 이미 로드된 옛 JS로 돌기 때문).
> 캐시가 남으면 주소 끝에 `?v=숫자`를 한 번 붙이세요.

## 단일 HTML로 쓰기

`build:single`로 만든 `dist-single/index.html` 하나면 됩니다. JS·CSS·워커·이미지가
전부 안에 들어 있어 **더블클릭해서 열면 바로 동작**합니다.

`file://`로 직접 열면 브라우저가 Web Worker 생성을 막아 **메인 스레드 파싱으로 자동
폴백**합니다(150MB 파일 실측 속도 차이 거의 없음 — 파싱이 CPU가 아니라 파일 읽기에 묶임).
단, `file://`에서는 카카오 지도가 뜨지 않아 **OSM 지도로 대체**됩니다(아래 "지도" 참고).

## 두 공간

| 공간 | 역할 |
|---|---|
| **블랙박스** | `.jdr` 열기 → 달력 → 운행 재생. 지도·센서·말한 구간·내보내기 |
| **이동기록** | 휴대폰 GPS 업로드 → 날짜별 동선 → 차량 GPS와 대조 → 주행/체류 분류 |

좌측 상단 전환기로 **HOME · 블랙박스 · 이동기록**을 오갑니다. OS/브라우저 뒤로가기는
한 단계씩 위로(재생→달력, 상세→목록, 목록→HOME) 가고, HOME에서 한 번 더 눌러야 나갑니다.

## 구현된 기능

### 블랙박스 (JDR 재생)

- **파일/폴더 열기** — `<input type="file">`, `webkitdirectory`, 드래그 앤 드롭(폴더 포함).
  `File.slice()`로 필요한 구간만 읽어 수 GB 폴더도 메모리에 올리지 않음
- **날짜 캘린더** — 폴더를 열면 월간 캘린더가 먼저. 날짜를 고르면 그 날짜만 로드.
  하루 안에서도 공백 10분 이상이면 **운행 단위**로 나눔. `data`/`event` 폴더는 나눠 선택
- **폴더 병합 재생** — 파일들을 기록 시각 순으로 이어 재생. 파일 경계 자동 전환(다음 구간
  미리 읽기), 빈 구간 자동 건너뛰기. 슬라이더·시간은 **현재 영상 파일 기준**
- **영상** — WebCodecs `VideoDecoder`로 전/후방 2채널, 변환 없이 재생. I-프레임 시크, 0.5~4배속
- **음성** — Web Audio로 PCM 8kHz. `AudioContext.currentTime`이 A/V 마스터 클럭
- **지도·차트** — 경로 폴리라인 + 재생 위치 마커, 속도/G센서 3축 차트(재생 커서 동기화)
- **말한 구간(대화 탭)** — VAD로 **대화가 있었던 시각을 색인**(전사 아님)하고 그 구간 음성만
  WAV로 추출 — 사람이 듣거나 전사 도구에 넘길 때 원본 파일·시각으로 되짚어 줌
- **즐겨찾기** — 재생 중 지점을 담아 파일로 주고받음(기기 간 이동, 감사 증빙)
- **내보내기** — 요약 JSON, GPS·G센서·패킷 CSV, WAV, **구간/범위 MP4**(전·후 합성 포함)
- **증거 추적성** — 현재 프레임의 출처 파일·구간 번호를 항상 표시. 스트리밍 SHA-256, 인덱스 불일치 표시

### 이동기록 (동선 대조)

- **휴대폰 GPS 업로드** — 도와줘 앱 내보내기(JSON/txt)를 올려 **날짜별로 병합** 저장(IndexedDB).
  하루 상한으로 잘린 기록도 여러 번 올려 채움(같은 시각 점은 하나로)
- **차량 GPS 대조** — 세 경로로 차량 GPS를 채움: ① 블랙박스에서 그날 스캔 시 자동 저장,
  ② **차량 GPS CSV 불러오기**, ③ **차량 JDR 폴더 열어 자동 대조**(영상은 안 읽고 인덱스에서
  GPS만 뽑음). 저장 후 휴대폰 동선과 자동 대조
- **분류** — 차량 GPS 근접(±시간·거리)·재계산 속도·체류시간으로 **이 차량 주행 / 보행 /
  체류 / 다른 이동**을 가림. 시간 막대·구간 표로 표시
- **머문 곳(체류)** — 원본 체류시간(staytime) 기준으로 도출해 지도에 굵게 표기.
  **상호명·주소**를 붙임 — 카카오 장소검색(Places, 반경 근접) + 못 찾으면 OSM 상호명,
  주소는 카카오 도로명 우선. 좌표별 캐시(IndexedDB)
- **전체 요약** — 여러 날짜를 한 번에 자동 대조·분석해 한 화면에(차량 유무·분류 시간·체류 요약),
  CSV로 내보내기
- **시간 스크러버** — 막대를 끌면 그 시각 좌표를 지도 중앙에 두고 따라가며, 막대 아래 시작·지금·끝 표시

## 지도

- **호스팅(등록 도메인, http/https)** → **카카오 지도**(국내 타일·주소, 감사에 유리) + 카카오
  장소검색으로 상호명.
- **`file://`·미등록 도메인** → SDK 인증이 막혀 **OSM(Leaflet)로 자동 대체**. 리버스 지오코딩도
  OSM Nominatim(초당 1회 준수)만 사용.
- `?map=kakao` / `?map=osm`로 강제 지정 가능.

## 구조

```
src/core/      플랫폼 독립 로직 (DOM 의존 없음 → 안드로이드 포팅 시 그대로 번역 가능)
  byte-source  ByteSource 추상화(Blob/ArrayBuffer) + WindowReader
  parser       JEB 블록·패킷·GPS·G센서 파싱
  segment      헤더만 읽는 프로브(타임라인용), 종료시각 보정
  duration     녹화 길이 온전성(꼬리 패킷·외톨이 프레임 제거) — 프로브·파서 공용
  records/scan 인덱스 테이블만 보고 GPS·센서 뽑기(전 구간 스캔)
  library      세그먼트 체인·빈 구간·겹침 계산
  index-file   폴더 인덱스(jdr-index.json) 내보내기/읽기
  nal/sha256   H.264 NAL·SPS 파싱, 스트리밍 SHA-256
  vad/speech   말한 구간 검출(VAD)·음성 추출
  export/mp4/range-export  CSV·WAV·JSON, MP4(전·후 합성), 범위 내보내기
  phone-track  도와줘 위치기록 파싱
  move-store   휴대폰 동선 저장·병합(IndexedDB)
  car-track-store  차량 GPS 저장 + CSV 파싱
  stays        체류(머문 곳) 도출
  track-match  차량·휴대폰 대조 분류(주행/보행/체류/이 차량)
  geocode      리버스 지오코딩(카카오 주입 + OSM) + 캐시
  bookmarks    즐겨찾기 저장/파일
src/worker/    파싱 워커
src/player/    WebCodecs 디코더, Web Audio, 재생 엔진
src/ui/        상단바·달력·요약·지도(map/kakao)·차트·이동기록·내보내기 패널
```

## 알아둘 점

### 브라우저 지원

| 브라우저 | 영상 재생 |
|---|---|
| Chrome / Edge / Opera 94+ | ✅ |
| Safari 26.0+ (macOS·iOS·iPadOS) | ✅ |
| Firefox 130+ (데스크톱) | ✅ |
| Firefox Android | ❌ WebCodecs 미지원 |

WebCodecs가 없어도 **요약·GPS·센서·이동기록·내보내기는 전부 동작**합니다. 영상만 비활성화됩니다.

### 코덱 수동 지정

코덱 자동 판별(SPS 파싱)이 실패하는 JDR 변형을 위해: `?codec=avc1.4D401E`

### 재생 최적화

프레임마다 파일을 읽으면 69초 영상 하나에 4,190회(초당 60회)가 됩니다. 모바일에서는 이
호출이 그대로 끊김이 되므로 **4MB 단위로 버퍼링**(4,190회 → 18회). 그 외
`hardwareAcceleration: 'prefer-hardware'`, 캔버스 `desynchronized: true`, 화면이 가려지면
자동 일시정지. 끊김 진단은 `?debug=1`.

### 성능 (70MB 실파일 기준 실측)

| 작업 | 1파일 | 읽는 양 | 828파일(58GB) 환산 |
|---|---|---|---|
| 프로브(타임라인) | 1ms | 1KB | 0.8초 |
| GPS·센서 스캔 | 19ms | 0.1MB | 선택한 날짜만 (하루 79개 ≈ 0.4초) |
| 재생용 파싱 | 59ms | 70MB | 구간별 지연 로드 |

전 구간 스캔은 파일을 통째로 파싱하지 않고 **12바이트 인덱스 테이블의 태그**로 GPS·센서
자리만 골라 읽습니다(전체 파싱이면 828개에 약 28분). **차량 JDR 폴더 자동 대조**도 같은
방식이라 45GB 폴더의 실제 읽는 양은 수십 MB 수준입니다.

폴더 열기(680개 실측): 최초 헤더 프로브 1.6초 → 브라우저 캐시 0.45초 → **인덱스 파일 0.42초
(1개·78.9KB만 읽음)**.

### 데이터는 어디에 남나 (IndexedDB)

| 저장소 | 내용 |
|---|---|
| `jdr-viewer-movement` | 휴대폰 동선(날짜별) |
| `jdr-viewer-cartrack` | 차량 GPS(날짜별) |
| `jdr-viewer-geocode` | 좌표→주소·상호명 캐시 |
| `jdr-viewer-bookmarks` | 즐겨찾기 |
| 프로브 캐시 | 헤더 프로브 결과 |

모두 그 브라우저 안에만 있습니다. 이동기록의 **전체 삭제**로 동선을 한 번에 비웁니다.
(포맷 식별자는 하위호환을 위해 `jdr-viewer-*`를 유지합니다.)

### 아직 안 한 것

- **PWA** — Service Worker / manifest (오프라인·홈 화면 추가·자동 업데이트)
- **충격 이벤트 자동 검출** — 합성 가속도 임계값 기반 점프
- 파싱이 파일을 두 번 읽음(해시+스캔 1회, 패킷 헤더 1회) — 블록 체인 추적으로 줄일 수 있음

## 면책

JDR 포맷 해석은 샘플에 대한 **역분석 추정**이며 제조사 공식 사양이 아닙니다.
GPS 속도·G센서 스케일(raw ÷ 1024 ≈ g), 동선 분류는 **추정/판정 보조 자료**입니다.
원본성 판단의 기준은 **원본 JDR 파일과 SHA-256**이며, 내보낸 결과물은 파생물입니다.
